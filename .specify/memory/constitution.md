# Personal LeetCode Workspace Constitution

## Core Principles

### I. Preserve the archive
LeetHub submissions, existing scratch files, and existing practice metadata remain usable in place. New practice solutions have a separate tracked path.

### II. Terminal and offline first
Use the installed tmux and Neovim configuration for interactive work. Local viewing, editing and testing operate offline after bootstrap.

### III. Explicit evidence and progress
Local tests report local outcomes. Learning status is an explicit decision. Online acceptance requires independent evidence.

### IV. Portable, deliberate Git sync
Use repository-relative data, local machine state outside tracked files, and explicit Git actions. Pull only by fast-forward from a clean checkout. Review paths before staging and pushing.

### V. Minimal dependencies
Reuse the kata fixtures, runner conventions and metadata. Keep editor integration local to the workspace and verify edge cases on real entry points.

## Governance

Update the spec and its acceptance scenarios when scope changes. Record the results of verification with the tasks.
